# Lab 04: Shared Counter — 트러블슈팅

이 랩은 하드웨어 검증 과정에서 특별한 이슈 없이 통과했습니다.

코드 리뷰 결과 M4 쪽 `mbox_rx_callback()`은 처음부터 수신 데이터를 큐에 넣기만 하고, 실제 처리(LED 점멸을 위한 블로킹 `k_msleep()` 호출)는 `Blink_Task` 워커 스레드에서 수행하도록 올바르게 작성되어 있어, Lab 03에서 발견됐던 "ISR 콜백 안에서 블로킹 호출" 버그가 애초에 발생하지 않았습니다. M55 쪽은 mbox 수신 콜백 자체가 없는 단방향(M55 → M4) 랩이라 해당 사항이 없습니다.

실기 테스트에서 M55 `counter=N sent`, M4 `counter=N received -> blinking LED0 M times` 및 실제 LED0 점멸까지 모두 정상 동작이 바로 확인되었습니다.

## 참고: 이전 랩에서 이미 해결되어 이 랩에도 적용된 공통 이슈

Lab 04를 포함한 모든 랩에 공통으로 적용되는, 이전 랩(Lab 01)에서 먼저 발견되고 해결된 이슈 두 가지가 있습니다. Lab 04 자체에서 재발한 것은 아니지만, 참고로 남깁니다.

- **M4/M55 I2C1 버스 공유 충돌**: M4와 M55가 물리적으로 같은 I2C1 버스(LED0/LED1/버튼이 매달린 `gpio_exp0`)를 공유하고 있어, 두 코어를 함께 빌드하면 부팅 시 버스 초기화 충돌이 발생합니다. `lab/boards/sr100_rdk_sr100_m55.overlay`에서 `&i2c1`, `&gpio_exp0`, `&ov02c10`을 `disabled`로 설정해 M4만 이 버스를 갖도록 정리되어 있습니다. 자세한 원인은 [Lab 01 문서](../../01_hello_ipc/doc/01_hello_ipc_kr.md) 참고.
- **`M4_BUILD` 상대경로**: `M4_BUILD`는 M55 빌드 디렉토리(`m55/`) 기준 상대경로로 해석됩니다. `m4/`와 `m55/`가 워크스페이스 루트의 형제 디렉토리 구조라면 `-DM4_BUILD="../m4"`가 정답이며, 잘못된 값을 주면 조용히(에러 없이) M4 펌웨어가 최종 flash 이미지에서 빠져 M4가 아무 것도 실행하지 못하는 상태가 됩니다.
